# Version 1.0: the Low findings fixed

Version 1.0 fixes the Low findings of [internal-review.md](internal-review.md) in new source files,
`contracts-v1/`. The deployed and BOTScan-verified 0.1 sources in `contracts/` are not touched, so
their verification stays valid; 0.1 purchases, offers and requests keep settling under the 0.1 rules
at their addresses. Version 1.0 runs on **testnet** since 2026-10-19 ([deployment](../../deployments/v1/968.json),
0.001 BOT cap per action like mainnet 0.1; [core flows](v1-testnet-core-flows.md): 20 / 20 transactions succeeded). A mainnet
1.0 is a separate decision (new addresses, see the README's cap-change plan).

Changed: `BazaarMarket`, `BazaarOffers`, `BazaarRequests`, `AgentPass` (each has `VERSION = "1.0"`).
Unchanged and reused from `contracts/`: `BazaarProjects`, `BotOrNot`, `PixelWorkshop`.
Constructor arguments are the same as 0.1, so `scripts/lib/localchain.mjs` deploys both.

| Finding | 0.1 behaviour | 1.0 change | Check |
|---|---|---|---|
| **L-1** payee that rejects BOT blocks its payout | `require(ok)` after each push payment: a rejecting seller, worker or buyer contract makes `confirm`, `release`, `accept`, `refund`, `cancel`, `cancelOffer` revert | Each payout is tried once with 100,000 gas and no return data copied; if it fails, the amount is credited to `owed[payee]` (`Owed` event) and the escrow settles anyway. The payee pulls it with `withdraw()`. `totalOwed` is public, so each contract's balance = escrow still held + `totalOwed`. | `test:local --v1`: rejecting seller, gas-burning seller, rejecting offer buyer, worker and poster; all settle, all withdraw |
| **L-2** `releaseMany` reverts as a whole | one unknown id or rejecting seller reverts the batch | unknown ids are skipped; payouts no longer revert (L-1) | `releaseMany([good, 99])` settles the good one |
| **L-3** shop item swap before `buyItem` | `buyItem(seller, index)` | `buyItem(seller, index, itemName)`: refused with "item changed" if the item at that index has another name | swap A→B at the same price; buying "A" is refused |
| **L-4** market dispute after the deadline | allowed until someone releases | `dispute` requires `now < releaseAt` ("late"), the same rule as `BazaarRequests` | dispute at 24 h + 1 s is refused; release works |
| **L-5** `acceptOffer` can front-run `cancelOffer` | race between two valid actions | no code change: the buyer is never worse off than with an acceptance a minute earlier (the purchase is escrowed, disputable and refundable). Kept as documented behaviour. | |
| **L-6** unused AgentPass permission cannot be cancelled | only `revoke` after linking | `cancelPermissions()` bumps the principal's nonce, so every signed, unused permission stops working | signature made, cancelled, `link` refused |

Client-facing ABI changes: `buyItem` takes the item name; new `owed`, `totalOwed`, `withdraw`,
`VERSION`; AgentPass `cancelPermissions`. The web client still uses 0.1 everywhere; switching a
network to 1.0 means pointing it at `deployments/v1/<id>.json` and passing the item name.

Trade-offs of the L-1 fix, for a reviewer: a payee contract that needs more than 100,000 gas to
receive BOT gets its money via `withdraw()` instead of directly, and a caller can provide too little
gas on purpose to force that; in both cases the money is credited to the right address and only
that address can take it.
